# Выкладка на 192.168.1.102

Требуется Linux-сервер с Docker Engine, Docker Compose, работающим BlueZ и Bluetooth-адаптером рядом с датчиком. Контейнер обращается к BlueZ хоста через `/run/dbus`; второй BlueZ внутри контейнера не нужен. Нужен обычный rootful Docker: доступ к D-Bus из rootless/userns режима требует отдельной настройки. Для SELinux возможна отдельная политика доступа; не меняйте метки системного `/run/dbus` через `:z`/`:Z`.

## Первый запуск на сервере

Из каталога проекта:

```sh
docker compose up -d --build --wait
```

Адрес: http://192.168.1.102:8088. При необходимости разрешите TCP 8088 в локальной сети. IP публикации можно изменить через `MI_BIND_IP`.

История и настройки находятся в томе `mi-temp-history`. Обычные обновления и `docker compose down` его сохраняют. Не используйте `down -v`, если нужна история.

Проверка здоровья контейнера проверяет HTTP/SQLite, а не доступность датчика: потеря Bluetooth не вызывает бесконечные перевыкладки. Соединение и свежесть показаний смотрите на странице и в `docker compose logs -f app`.

## Автоматическая сборка и выкладка

1. Разместите проект в приватном GitHub-репозитории, основная ветка `main`.
2. На сервере установите отдельный GitHub Actions runner для этого репозитория: Settings → Actions → Runners → New self-hosted runner. Выполните выданные GitHub команды под отдельным пользователем. Добавьте метку `mi-temp`, установите runner как службу.
3. Пользователю runner нужен доступ к Docker (`docker info` должен работать без sudo). Этот доступ даёт полномочия управления хостом; runner должен выполнять только доверенный код этого проекта.
4. Push в `main` запускает сборку, тесты в контейнере и обновление приложения. Также доступен ручной запуск Actions → Build and deploy → Run workflow.

Runner работает непосредственно на 192.168.1.102, поэтому ни SSH-ключ в GitHub, ни открытие SSH в интернет, ни реестр образов не нужны. При неуспешной проверке HTTP выполняется попытка возврата к предыдущему образу. Смена схемы БД требует отдельной стратегии миграции; откат образа не откатывает данные.

Токен регистрации runner берите в GitHub непосредственно перед настройкой, не сохраняйте в репозитории. Не включайте выполнение произвольных pull request на этом runner.

## Перенос существующей истории

Перед переносом остановите сбор на прежнем компьютере через Ctrl+C и дождитесь отключения Bluetooth. Одновременно старый сервер и контейнер запускать не нужно. Для целостной копии используйте SQLite backup API, затем перенесите получившуюся базу на сервер. До первого запуска приложения положите её в том `mi-temp-history` как `readings.sqlite3`. Не заменяйте уже работающую базу без резервной копии.

Если перенос истории не нужен, первый запуск создаст пустую базу.
